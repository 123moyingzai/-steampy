# 图片路径说明

本文说明项目里图片从「数据库字段」到「浏览器能显示」的完整链路，改图 / 加图 / 排查图片不显示时先看这里。

## 1. 数据库存的是什么

三张表都有图片字段，**存的是路径字符串，不是图片文件本身**：

| 表 | 字段 | 说明 |
|----|------|------|
| `games` | `image` | 游戏主封面 |
| `orders` | `game_image` | 下单时快照，不随 games 变化 |
| `listings` | `game_image` | 上架时快照，不随 games 变化 |

> 快照设计：改 `games.image` 后，`orders` / `listings` 里的历史记录**不会自动更新**，需要显式同步（见第 5 节）。

## 2. 三种合法取值

| 格式 | 示例 | 含义 |
|------|------|------|
| CDN 在线地址 | `https://cdn.akamai.steamstatic.com/steam/apps/730/header.jpg` | Steam 官方封面，直接用 |
| 本地相对路径（推荐） | `../picture/games/三更.jpg` | 仓库内的本地图 |
| 本地相对路径（旧格式） | `../picture/安魂曲.jpg` | 历史数据，仍兼容，但不推荐新写入 |
| 空 / null | `` | 前端显示兜底图 |

不要写 `/uploads/...`：那是运行时上传目录，不进版本库，队友拉代码后会 404。

## 3. 前端如何解析（唯一入口）

`src/composables/useGameImage.ts` 导出统一方法，页面不要再自己拼路径。

```ts
getImageUrl(image)      // DB 值 → 浏览器可用 URL
onImgError(e)           // <img @error> 兜底，失败切默认图
toDbImage(url)          // 浏览器路径 → DB 存储格式（写入时用）
```

转换规则：

```
https://...                  → 原样返回（Steam CDN）
../picture/games/xxx.jpg     → /picture/games/xxx.jpg
../picture/xxx.jpg           → /picture/xxx.jpg（兼容旧格式）
空 / null                    → /picture/games/安魂曲.jpg（兜底图）
```

**为什么必须转换**：DB 里的 `../picture/...` 是相对路径，在 `/admin/orders` 这类子路由下会被解析成 `/admin/picture/...`，必然 404。统一转成 `/picture/...` 才是站根绝对路径。

## 4. 图片文件放哪（两处必须同时存在）

| 目录 | 作用 |
|------|------|
| `public/picture/` | 前端源码目录，Vite dev（5173）直接 serve |
| `backend/src/main/resources/static/picture/` | 打包进 jar，后端（8080）serve |

目录结构：

```
public/picture/
├── games/                 # 游戏封面（DB 引用的本地图都在这里）
├── orphan-cache/          # 历史缓存图（当前无 DB 引用，可清理）
├── header.jpg             # 首页 Banner
├── gun1.png gun2.png gun3.png   # 轮播图
└── 屏幕截图 2025-12-03 134029.png
```

`backend/src/main/resources/static/picture/` 保持同样的结构（从 `dist/picture` 同步）。

## 5. 改图 / 换图的标准流程

1. 把图片放进 `public/picture/games/`，文件名建议英文或与游戏名一致
2. 同步到后端：`npm run build` 后把 `dist/picture` 复制到 `backend/src/main/resources/static/picture`
3. 改数据库 **三张表一起改**：

```sql
UPDATE games    SET image      = '../picture/games/新图.jpg' WHERE id = ?;
UPDATE orders   SET game_image = '../picture/games/新图.jpg' WHERE game_id = ?;
UPDATE listings SET game_image = '../picture/games/新图.jpg' WHERE game_id = ?;
```

4. 重新打包 jar 并重启（否则 8080 还是旧图）

## 6. 新增游戏时的自动封面

管理端「新增游戏 → AI 自动填写」会从 Steam 官方接口取 `apps/{AppID}/header.jpg`。

保存时若图片地址仍是 `http(s)`，后端会调用 `/api/upload/remote-image` 把图下载到 **`backend/uploads/games/`**（AppID 命名）。该目录是运行时目录，**不进版本库**，只适合本机使用；需要随代码分发时，按第 5 节把它复制进 `public/picture/games/` 并改 DB 路径。

## 7. 排查「图片不显示」

| 现象 | 检查点 |
|------|--------|
| 只有个别游戏挂 | `SELECT image FROM games WHERE id=?`，看 AppID 是否正确（可能指向别的游戏） |
| 路径里出现 `?` | 中文被 GBK 转换损坏，用 `HEX(image)` 确认，按第 5 节改回 |
| 全部本地图挂 | `public/picture/` 与 `static/picture/` 是否同步；jar 是否重新打包 |
| 子路由下挂、首页正常 | 页面没走 `getImageUrl()`，用了裸 `game_image` |
| 换了图但显示旧的 | 浏览器缓存，Ctrl+Shift+R；或 jar 没重打包 |

快速校验（文件名存在 + HTTP 可达）：

```bash
mysql -u root -p --default-character-set=utf8mb4 -e "SELECT DISTINCT image FROM games WHERE image LIKE '../picture%';" steampy
curl -I http://localhost:8080/picture/games/三更.jpg
```
